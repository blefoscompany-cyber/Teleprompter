# Implementation notes

The capture session uses a dedicated serial queue. Configuration/start/stop and movie-output delegate events share this queue; SwiftUI receives state changes on the main queue. A separate queue-owned recording phase protects against rapid double taps, early Stop, camera changes, and asynchronous delegate callbacks.

The built-in wide camera is discovered separately for front/rear. All device formats are described by dimensions and supported frame-rate ranges. The pure selector favors requested exact resolution/FPS, then supported lower configurations, with no index assumption. `.inputPriority` preserves explicit `activeFormat`; both frame durations are set to 1/FPS. SDR/full-range 8-bit is preferred, HDR automation is disabled, and stabilization is off to avoid additional format constraints. The UI reports the selected active format, not independently measured file properties. File quality remains a real-device acceptance test.

`AVCaptureMovieFileOutput` muxes microphone audio and video to a local MOV. HEVC is selected when available; H.264 is the native fallback. There is no AVAssetWriter, UI screenshot capture, duration limit, or memory accumulation of video frames. AVFoundation owns AV synchronization and streaming-to-disk. A small storage reserve is a disk-safety threshold, not a duration cap.

The application explicitly owns `AVAudioSession` (`playAndRecord`, `videoRecording`); capture-session automatic configuration is disabled. The session is reactivated after audio interruptions when foreground capture is desired. Recording stops on audio/capture interruption, critical thermal state or backgrounding, then waits for finalization. iOS background-task time protects finalization only; it does not enable background camera use. Serious heat and low storage generate warnings; no periodic duration check stops a take.

Preview orientation comes from the active window scene's interface orientation, avoiding physical device orientation reversal and face-up ambiguity. The corresponding movie connection orientation is set once immediately before recording. Front preview stays mirrored independently. Movie output mirroring is set once before recording from the captured Mirror Recorded Video preference (default true) and the queue-owned selected camera side. Rear output is always non-mirrored. Automatic output mirroring is disabled before assigning the desired value; unsupported requested mirroring refuses the take with an actionable error instead of silently recording the wrong appearance. Preview layer layout remains on the main thread, while capture mutations remain on the session queue. iOS 17 deprecated `videoOrientation` in favor of rotation angles, but the supported API remains used here for its simple orientation mapping; this should be reassessed if Apple removes it from future SDKs. No camera connection orientation changes are made mid-take.

Teleprompter scrolling is a native read-only UITextView driven by a 30 Hz CADisplayLink. It updates content offset, not SwiftUI state, each animation frame. Main-screen SwiftUI state only changes for user edits/settings and coarse recording state. A separate one-second TimelineView displays elapsed time. Manual drag pauses the display link; a weak proxy and explicit dismantling prevent an animation retain cycle.

Script and simple settings use UserDefaults with no network integration. Retained recordings use Documents/Recordings, excluded from backup, and are discoverable after relaunch. Add-only Photos permission is requested; async Photos transactions must succeed before local deletion. Failed/incomplete files stay available for export. No user content enters build logs or fixtures. Ordinary device backups for app preferences are controlled by iOS/user settings, not by an app cloud-sync feature.

Free signing is delegated to AltStore Classic on Windows. GitHub generates an unsigned device app and packages it directly. There is no archive export requiring Apple provisioning, no entitlements for paid services, and no certificate/provisioning upload. XcodeGen derives Info.plist from project.yml. CI runs unit tests on a discovered installed iPhone simulator; physical camera QA is separate.
